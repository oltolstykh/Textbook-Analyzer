## Что уже есть

Анализатор учебника (Textbook Analyzer) – статический браузерный инструмент без сервера, работает из файла и с GitHub Pages. Два режима на общем ядре – «Инструкции» (A1-A7, D1, D3, D4, ИСВ, рубрика R1-R6, D1, D2, D4, D5) и «Тексты» (T1-T4, оценка уровня L, ИСТ, рубрика TR1-TR6, пары «инструкция – текст», R6). Импорт из учебника (PDF, DOCX, веб-страница) сам находит уроки, номера упражнений и инструкции и сохраняет порядок упражнений. Интерфейс двуязычный (RU / EN).

Ключевые решения, которые нужно сохранить
- все алгоритмические показатели приведены к шкале 0-1, рубрика 2-1-0 переводится в 0, 0,5 и 1;
- инструмент не выносит вердикт, а показывает зоны для экспертного взгляда;
- рубричные критерии оценивают эксперт и языковая модель (Groq или ручной промпт), согласованность – взвешенная каппа Коэна;
- протокол JSON хранит версии эталонов, настройки и все оценки;
- ключ Groq хранится только в браузере;
- данные пользователя в localStorage под ключом `textbook-analyzer-v1`.

## Задача

Добавить в анализатор оценку методической стороны упражнений – уровень задания, его тип и место в последовательности упражнений урока, а также уместность задания. Основание – учебники по методике обучения иностранным языкам, которые загрузит Олеся.

### Решения, которые нужно принять до начала
1. На какие классификации опираться в первую очередь – типология упражнений С.Ф. Шатилова (языковые, условно-речевые, речевые), логика Е.И. Пассова (от формирования навыка к развитию умения), пересмотренная таксономия Блума (Anderson, Krathwohl, 2001) или две линии одновременно (отечественная как основная, Блум – для сопоставления с зарубежными работами). Олеся предпочитает доводы и примеры из методики обучения иностранным языкам и термины отечественной школы.
2. Какие главы загруженных учебников использовать (типология упражнений, построение урока, этапы работы над навыком и умением).
3. Указывать ли цель урока в данных (новое необязательное поле) или поручать модели выводить её из заголовка и материала урока.

### 1. Эталоны из учебников по методике
- Выписать из загруженных источников типологии упражнений, признаки каждого типа, правила последовательности (что должно предшествовать речевому упражнению, этапы ознакомления, тренировки и применения, ожидаемые соотношения типов на этапе).
- Оформить как новый раздел эталонов в `js/resources.js` с версией (например, method-0.1) и ссылкой на источник у каждого правила.
- В инструмент и на GitHub попадают только критерии своими словами и библиографические ссылки, без фрагментов текста учебников. Выходные данные источников сверять по самим файлам, ничего не брать по памяти.

### 2. Алгоритмические показатели
- **Тип упражнения** для каждой инструкции – по глаголу-установке, типу задания, наличию образца, опор, речевой ситуации и материала упражнения (exercise_text). Результат – тип по выбранной классификации и надёжность определения.
- **Когнитивный уровень** (если решено использовать Блума) – по глаголу и типу задания, с учётом того, что один глагол может относиться к разным уровням (Describe с образцом и без него).
- **Последовательность в уроке** – по порядку упражнений: профиль урока (линия типов или уровней), отметки скачков (речевое задание без предшествующей тренировки нужного материала), возвратов и пропущенных этапов. Показатель урока по шкале 0-1.
- Новые показатели не должны менять числа существующих критериев – проверка `node tests/regress.js`. Для новых показателей – отдельный проверочный набор в `tests/`.

### 3. Рубричные критерии
- **Уместность задания** – соответствует ли упражнение цели урока, этапу и уровню группы. Формулировки баллов 2, 1, 0 – по загруженным источникам.
- При необходимости – критерий последовательности урока для эксперта (оценивается урок, а не отдельная инструкция).
- Промпты для модели – с теми же критериями, версия промпта повышается.

### 4. Интерфейс
- Тепловая карта – новые столбцы для инструкций, новый вид «Последовательность урока» (упражнения по порядку, тип или уровень каждого, отметки скачков).
- Карточка инструкции – тип, уровень, обоснование (по какому признаку определено), место в уроке.
- Статистика – распределение типов и уровней по учебникам и урокам, типичные нарушения последовательности.
- Выводы – новые правила для автоматических выводов.
- Настройки – выбор классификации, пороги.
- Все новые русские строки – через `_t()`, с переводом в `js/i18n-en.js`. Проверить английскую версию на отсутствие русского текста.

### 5. Документация
- Обновить `docs/methodology.md` (новый раздел – обоснование классификаций и правил с источниками), `docs/user-guide.md`, `README.md` и `README.ru.md`.
- Повысить версии (engine, res, ui, prompt), записать их в протокол.

### 6. Проверка и валидация
- Браузер (headless Chromium) – оба языка, все вкладки, ошибки консоли, ширина 390 px.
- Пример – дополнить вымышленные учебники в `js/sample.js` и `examples/` так, чтобы в примере были и правильная последовательность, и нарушения.
- План валидации для статьи – разметка 30-50 инструкций и 5-10 уроков экспертами, каппа между экспертами и между экспертом и алгоритмом.
